# S2.6 — Retrieval Benchmark & Evaluation Harness (Task Summary)

**Task:** BARQ G4 · Sprint 2 (S2.6)
**Objective:** Automated harness to benchmark the retrieval pipeline against ground-truth incidents and negative controls.
**Constraint:** Benchmark-only — no changes to agent, embedding, or retrieval code.

**Status:** Calibrated 2026-09-21 against the live `kb_chunks` collection
(33 articles / 211 chunks, 768-dim): **65.0% hit @ 0.75, 100% refusal,
100% ranking accuracy**; sweep recommends threshold **0.70 → 95% / 100%**.
See `RETRIEVAL_EVALUATION.md` and `benchmark_results.json`.

## Scope coverage

| Scope item | Status |
|---|---|
| Structured dataset, ≥10 answerable (incident + expected articles) | 20 answerable in `benchmark_dataset.json` (incl. 5 paraphrase/typo variants) |
| Structured dataset, ≥3 negative controls | 10 negatives (5 far-out-of-domain + 5 IT-adjacent near-miss) |
| Single-command runner | `uv run python benchmark/run_benchmark.py [--real]` |
| Aggregate metrics: Hit Rate + Refusal Correctness | Printed + saved to `benchmark_results.json` |
| Per-incident output (pass/fail, scores, expected vs retrieved) | Console log + `answerable_details` / `negative_details` |
| Score-distribution analysis + threshold sweep | `RETRIEVAL_EVALUATION.md`; sweep in results JSON |

## Files (all inside `benchmark/`)

- `benchmark_dataset.json` — 30 cases (incident text, category, expected articles, control notes)
- `run_benchmark.py` — runner (incident-text queries, ungated retrieval + Python gate, sweep)
- `benchmark_results.json` — generated on run (provenance, metrics, distributions, per-case detail)
- `RETRIEVAL_EVALUATION.md` — methodology + how to run + threshold guidance
- `S2.6_TASK.md` — this file

## How to run

```bash
uv run python benchmark/run_benchmark.py            # stub (offline plumbing check)
uv run python benchmark/run_benchmark.py --real     # real Gemini embeddings
uv run python benchmark/run_benchmark.py --threshold 0.65 --real --top-k 5
```
